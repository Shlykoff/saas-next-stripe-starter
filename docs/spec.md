# SaaS-стартер с подпиской (флагман)

**Стек:** Next.js 14+ (App Router, Server Actions) · Supabase (Auth + Postgres + RLS) · Stripe (Checkout, Customer Portal, Webhooks) · Tailwind + shadcn/ui · Vercel · TypeScript.

**Функционал MVP:**
1. Регистрация/логин через Supabase Auth (email+пароль и один OAuth-провайдер, например Google).
2. Онбординг: создание workspace/организации после регистрации.
3. Страница тарифов с 2-3 планами → Stripe Checkout Session.
4. Личный кабинет с текущим статусом подписки, кнопка "Manage billing" → Stripe Customer Portal.
5. Обработка `checkout.session.completed`, `customer.subscription.updated/deleted`, `invoice.payment_failed` через webhook-эндпоинт с проверкой подписи.
6. Row Level Security: каждый пользователь видит только данные своей организации; отдельная политика для service role.
7. Простая "продуктовая" фича внутри (например, список задач или заметок), доступная только с активной подпиской — чтобы показать gating по статусу оплаты.

**Best practices, которые обязательно нужно применить:**
- Проверка `stripe-signature` заголовка на вебхуке (`stripe.webhooks.constructEvent`), а не доверие телу запроса.
- Идемпотентность обработки вебхуков (защита от повторной доставки одного и того же события).
- `service_role` ключ Supabase используется **только** на сервере (route handlers/server actions), никогда в клиентском коде.
- RLS-политики написаны явно на каждую таблицу, включён "deny by default".
- Разделение test/live режимов Stripe через переменные окружения.
- Graceful обработка отменённой/просроченной подписки в UI (баннер "переоформите подписку").

**Данные для README:** тестовые карты Stripe, тестовый логин, ссылка на Customer Portal.

## Общие правила

- **TypeScript strict mode** включён везде, без `any` без необходимости.
- **Секреты только в `.env`**, добавлен `.env.example` с плейсхолдерами. Ни один ключ не закоммичен в историю git.
- **README**: что делает проект → стек → живое демо (ссылка) → как запустить локально (`git clone` → `npm i` → `.env` → `npm run dev`) → скриншоты/GIF → ключевые технические решения (2-3 абзаца — почему так, а не иначе).
- **Демо-доступ для клиента**: тестовый логин/пароль или "Try demo" кнопка без регистрации, тестовые карты Stripe (4242 4242 4242 4242) явно указаны в README.
- **Обработка ошибок и edge cases** — не happy-path-only код: пустые состояния, невалидный ввод, таймауты, retry там где уместно.
- **Минимум тестов** — несколько unit/integration тестов на критичную логику (webhook-обработчик, RLS-политику, API-эндпоинт). Наличие папки `tests/`.
- **CI на GitHub Actions** — простой workflow (lint + test) на пуш. Значок "build passing" в README.
- **Деплой на Vercel/Railway/Render**, публичная рабочая ссылка обязательна.
- **Коммит-история осмысленная**, а не один коммит "initial commit". Делайте по фичам.
